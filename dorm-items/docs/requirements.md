# 기숙사 공용 물품 관리 서비스 개발 문서

## 1. 프로젝트 개요

기숙사 공용 물품의 예약과 사용·반납 여부를 관리하는 웹 서비스이다. 학생은 물품의 지정 보관 장소와 이용 가능 시간을 확인하고 예약할 수 있다. 사용 후에는 지정된 장소에 반납하고 서비스에 반납 완료 상태를 등록한다.

- **대상 사용자:** 기숙사 학생, 공용 물품 관리 담당 학생
- **해결할 문제:** 물품의 예약 현황과 사용·반납 여부를 확인하기 어렵다.
- **기대 효과:** 중복 이용을 방지하고, 다른 학생이 물품의 반납 여부를 확인할 수 있다.

반납 장소는 물품별로 미리 정해져 있다. 사용자는 위치를 입력하거나 변경하지 않으며, 서비스는 사용자가 등록한 내용을 바탕으로 반납 여부를 표시한다.

## 2. 필수 기능

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| F1 | 물품 목록 조회 및 검색 | 이름이나 종류로 검색하고 지정 보관 장소와 이용 상태를 확인한다. |
| F2 | 물품 등록 및 수정 | 관리자가 물품 정보, 지정 보관 장소, 이용 가능 시간을 관리한다. |
| F3 | 예약 가능 시간 조회 및 예약 | 시간표를 확인하고 이용 가능한 시간에 물품을 예약한다. |
| F4 | 예약 취소 및 내역 조회 | 자신의 예약을 확인하고 사용 전 예약을 취소한다. |
| F5 | 사용 시작 및 반납 완료 등록 | 사용 시작을 기록하고, 사용 후 반납 완료 상태를 등록한다. |
| F6 | 이용 기록 조회 | 물품별 예약 시간과 실제 사용·반납 시각을 확인한다. |
| F7 | AI 이용 기록 요약 | 관리자가 이용 집중 시간대와 반납 지연 등의 이용 패턴을 확인한다. |

로그인과 권한 구분, 데이터 보존은 기본 기능으로 구현한다. 알림과 학교 계정 연동은 추가 기능으로 분류한다.

## 3. 사용자 권한

| 사용자 | 가능한 작업 |
| --- | --- |
| 학생 | 물품 조회·검색, 예약·취소, 본인 예약 조회, 사용 시작, 본인 이용 건의 반납 완료 등록 |
| 관리자 | 물품·운영 시간 관리, 전체 이용 기록 조회, 예외 반납 처리, AI 요약 조회 |

사용자와 권한은 서버의 로그인 정보로 확인한다. 학생은 다른 학생의 예약이나 이용 상태를 변경할 수 없다.

## 4. 대표 사용 시나리오

### 물품 예약과 반납 완료 등록

1. 학생이 로그인하고 ‘청소기’를 검색한다.
2. 서비스가 지정 보관 장소와 현재 이용 상태를 보여준다.
3. 학생이 예약 가능 시간을 확인하고 14시부터 15시까지 예약한다.
4. 서비스가 예약 중복 여부를 확인하고 예약을 저장한다.
5. 학생이 예약 시간에 ‘사용 시작’을 누르면 ‘사용 중’으로 표시한다.
6. 학생이 사용을 마치고 청소기를 지정된 장소에 반납한다.
7. 학생이 자신의 이용 화면에서 ‘반납 완료’를 누른다.
8. 서비스가 반납 완료 상태와 등록 시각을 저장한다.
9. 다른 학생은 물품 화면에서 반납 여부와 현재 이용 상태를 확인한다.

반납 완료 등록은 사용자의 확인에 근거한다. 실제 물품이 지정 장소에 있는지를 자동으로 감지하는 기능은 제공하지 않는다.

### 관리자의 이용 현황 확인

1. 관리자가 조회 기간을 선택한다.
2. 서비스가 예약·사용·반납 기록을 표시한다.
3. 관리자가 AI 요약을 요청한다.
4. 서비스가 이용 집중 시간대와 반납 지연을 요약한다.
5. 관리자는 요약과 원본 기록을 함께 확인한다.

## 5. 운영 규칙

### 예약

- 예약은 물품별 운영 시간 안에서만 가능하다.
- 30분 단위로 예약하며, 한 번에 최대 2시간 이용할 수 있다.
- 과거 시간이나 기존 예약과 겹치는 시간은 예약할 수 없다.
- 14~15시 예약 다음에 15~16시 예약은 가능하다.
- 예약은 본인의 사용 시작 전에만 취소할 수 있다.
- 예약만으로 물품이 ‘사용 중’으로 변경되지는 않는다.

### 사용과 반납

- 본인의 예약 시간에만 사용을 시작할 수 있다.
- 이미 다른 학생이 사용 중이면 사용 시작을 거절한다.
- 사용 후 지정 장소에 반납하고 ‘반납 완료’를 등록한다.
- 반납 화면에는 위치 입력 항목을 제공하지 않는다.
- 반납 완료 시각은 서버가 등록 시점에 기록한다.
- 예약 종료 시간이 지나도 자동으로 반납 완료 처리하지 않는다.
- 미반납 상태가 계속되면 반납 지연으로 표시한다.
- 반납 완료는 해당 이용자 또는 관리자만 등록할 수 있다.

### 상태 구분

| 구분 | 상태 | 의미 |
| --- | --- | --- |
| 예약 | 예약 완료 | 예약이 정상적으로 저장됨 |
| 예약 | 예약 취소 | 사용 전에 예약을 취소함 |
| 이용 | 사용 중 | 사용을 시작했고 반납 완료를 등록하지 않음 |
| 이용 | 반납 완료 | 사용자가 지정 장소에 반납했다고 등록함 |

물품 화면에서는 미반납 이용 기록이 있으면 ‘사용 중’, 없으면 ‘사용 가능’으로 표시한다. 미래 시간의 예약 가능 여부는 시간표에서 별도로 확인한다.

## 6. 기능 요구사항과 완료 기준

### F1. 물품 목록 조회 및 검색

- **입력:** 검색어, 물품 종류
- **정상 처리:** 물품명, 종류, 지정 보관 장소, 현재 이용 상태를 표시한다.
- **실패 처리:** 검색 결과 없음과 조회 오류를 구분해 안내한다.
- **완료 기준:** 이름·종류로 검색하고 물품 정보와 예약 화면을 확인할 수 있다.

### F2. 물품 등록 및 수정

- **입력:** 물품 코드, 이름, 종류, 설명, 지정 보관 장소, 운영 요일·시간
- **정상 처리:** 관리자 입력을 저장하고 조회 화면에 반영한다.
- **실패 처리:** 필수 정보 누락, 중복 코드, 잘못된 시간, 권한 없는 요청을 거절한다.
- **완료 기준:** 등록·수정한 정보가 재조회와 재실행 후에도 유지된다.

지정 보관 장소는 관리자가 관리하는 물품 정보이다. 학생의 반납 완료 등록으로 변경되지 않는다. 기존 예약을 운영 시간 밖으로 만드는 시간 변경은 거절한다.

### F3. 예약 가능 시간 조회 및 예약

- **입력:** 물품 ID, 날짜, 시작·종료 시각
- **정상 처리:** 운영 시간과 기존 예약을 확인한 후 예약을 저장한다.
- **실패 처리:** 중복 시간, 과거 시간, 운영 시간 밖의 예약을 거절한다.
- **완료 기준:** 예약 불가 구간을 선택할 수 없고, 같은 구간의 동시 요청은 하나만 승인된다.

예약 저장 직전에 서버에서 최신 예약 현황을 다시 검사한다.

### F4. 예약 취소 및 내역 조회

- **입력:** 예약 ID
- **정상 처리:** 자신의 예약을 조회하고 사용 전 예약을 취소한다.
- **실패 처리:** 타인의 예약이나 이미 사용을 시작한 예약의 취소를 거절한다.
- **완료 기준:** 취소 내역이 보존되고 해당 시간에 새로운 예약이 가능하다.

### F5. 사용 시작 및 반납 완료 등록

- **입력:** 사용 시작 시 예약 ID, 반납 완료 시 이용 기록 ID
- **정상 처리:** 사용 시작 시 ‘사용 중’과 시작 시각을 저장한다. 반납 완료 요청 시 ‘반납 완료’와 등록 시각을 저장한다.
- **실패 처리:** 예약 시간 밖 사용, 중복 사용 시작, 타인의 반납 요청을 거절한다.
- **완료 기준:** 반납 완료 등록 후 다른 사용자도 반납 여부를 확인할 수 있고, 지정 보관 장소는 그대로 유지된다.

중복 클릭이나 요청 재전송으로 이용 기록이 추가 생성되지 않아야 한다. 이미 반납한 이용 건은 기존 반납 완료 결과를 반환한다.

### F6. 이용 기록 조회

- **입력:** 물품 ID, 조회 기간
- **정상 처리:** 예약 시간, 실제 사용 시작 시각, 반납 완료 등록 시각, 반납 지연 여부를 표시한다.
- **실패 처리:** 기록 없음과 조회 오류를 구분해 안내한다.
- **완료 기준:** 학생은 본인 내역을 확인하고, 관리자는 전체 이용 기록을 확인할 수 있다.

물품의 공용 조회 화면에서는 다른 학생의 개인 식별 정보를 공개하지 않고 사용·반납 여부만 표시한다.

### F7. AI 이용 기록 요약

- **입력:** 조회 기간
- **정상 처리:** 이용 빈도, 예약 집중 시간대, 반납 지연 등의 패턴을 요약한다.
- **실패 처리:** 기록이 없으면 호출하지 않는다. 외부 API 실패 시 원본 기록과 집계를 제공한다.
- **완료 기준:** 요약의 근거를 원본 기록에서 확인할 수 있고, AI 장애가 기본 기능에 영향을 주지 않는다.

## 7. 주요 확인 사례

| 번호 | 시작 상태와 행동 | 기대 결과 |
| --- | --- | --- |
| T1 | 청소기를 이름으로 검색 | 지정 보관 장소와 이용 상태 표시 |
| T2 | 없는 물품명 검색 | 검색 결과 없음 안내 |
| T3 | 비어 있는 시간에 예약 | 예약 1건 저장 |
| T4 | 기존 예약과 겹치는 시간 요청 | 예약 거절, 기존 데이터 유지 |
| T5 | 두 학생이 같은 구간에 동시 예약 | 하나만 성공 |
| T6 | 본인의 사용 전 예약 취소 | 취소 저장, 해당 구간 예약 가능 |
| T7 | 타인의 예약 취소 요청 | 권한 오류, 기존 예약 유지 |
| T8 | 예약 시간에 사용 시작 | 사용 중 상태와 시작 시각 저장 |
| T9 | 사용자가 지정 장소에 반납한 뒤 반납 완료 등록 | 반납 완료 상태와 등록 시각 저장, 보관 장소 변경 없음 |
| T10 | 다른 학생이 물품 상태 조회 | 반납 완료 여부와 현재 사용 가능 상태 확인 |
| T11 | 타인의 이용 건에 반납 완료 요청 | 요청 거절, 이용 상태 유지 |
| T12 | 이미 반납한 건을 다시 반납 요청 | 기존 결과 반환, 기록과 반납 시각 유지 |
| T13 | 이전 사용자가 미반납한 상태에서 다음 예약자가 사용 시작 | 시작 거절, 미반납 안내 |
| T14 | 반납 저장 중 오류 발생 | 반납 상태·시각·이력 모두 변경 취소 |
| T15 | AI 요청 실패 | 실패 안내, 원본 기록 조회 유지 |
| T16 | 서비스와 DB 재실행 | 물품·예약·이용 기록 유지 |

## 8. 시스템 구성과 데이터 흐름

### 시스템 구성

브라우저 → Flask 웹 서버 → PostgreSQL

Flask 웹 서버 → 외부 LLM API

| 구성요소 | 역할 |
| --- | --- |
| 웹 화면 | 물품 검색, 예약 시간표, 내 예약, 사용·반납 완료 화면 |
| Flask 서버 | 로그인·권한 확인, 예약 검증, 사용·반납 처리 |
| PostgreSQL | 물품·예약·이용 기록과 변경 이력 보관 |
| 외부 LLM API | 이용 기록과 집계에 근거한 요약 |

### 예약 처리

1. 사용자가 물품과 예약 시간을 전송한다.
2. 서버가 사용자와 운영 시간을 검증한다.
3. 같은 물품의 예약 요청을 순서대로 검사해 중복을 방지한다.
4. 예약을 저장한 뒤 결과를 반환한다.

### 반납 완료 처리

1. 사용자가 ‘반납 완료’를 누른다.
2. 서버가 본인의 사용 중인 이용 건인지 확인한다.
3. 반납 완료 상태, 등록 시각, 처리 이력을 함께 저장한다.
4. 물품의 사용 중 표시를 해제한다.
5. 다른 사용자의 조회에 갱신된 이용 상태를 표시한다.

반납 완료 처리에서는 지정 보관 장소를 수정하지 않는다. 저장 중 오류가 발생하면 관련 변경을 모두 취소한다.

## 9. 데이터 설계

| 데이터 | 주요 항목 |
| --- | --- |
| 사용자 | 사용자 ID, 계정, 비밀번호 해시, 권한 |
| 물품 | 물품 ID, 고유 코드, 이름, 종류, 설명, 지정 보관 장소 |
| 운영 시간 | 물품 ID, 요일, 이용 시작·종료 시각 |
| 예약 | 예약 ID, 물품 ID, 사용자 ID, 시작·종료 시각, 예약 상태 |
| 이용 기록 | 이용 ID, 예약 ID, 이용 상태, 사용 시작 시각, 반납 완료 등록 시각 |
| 처리 이력 | 이용 ID, 처리자, 변경 전후 상태, 처리 시각 |

물품 한 개에 여러 예약이 연결되며, 예약 한 건에는 이용 기록이 최대 한 건 연결된다. 반납 완료 등록 시각이 없는 사용 기록을 기준으로 현재 사용 중 여부를 판단한다.

## 10. AI 처리 방식

서버가 예약 건수, 시간대별 예약 빈도, 사용 시간, 반납 지연 건수를 계산한다. LLM은 집계와 관련 기록을 바탕으로 주요 이용 패턴을 요약한다.

- 예약 기준 통계와 실제 사용 기록을 구분한다.
- 반납 시각은 사용자가 반납 완료를 등록한 시각임을 표시한다.
- 이름·학번·호실 등 개인 식별 정보는 전달하지 않는다.
- 요약에는 근거 기록을 연결한다.
- AI는 예약이나 반납 상태를 자동 변경하지 않는다.
- 외부 API 실패 시 집계와 원본 기록을 계속 제공한다.

## 11. 실행과 구현 계획

Docker Compose로 Flask 서버와 PostgreSQL을 실행한다. 데이터는 영속 볼륨에 저장하고 접속 정보와 API 키는 환경 변수로 관리한다. 외부 배포 시 HTTPS를 적용한다.

### 구현 순서

- [ ] 로그인과 권한 구분
- [ ] 물품 등록·수정과 목록·검색
- [ ] 운영 시간과 예약 시간표
- [ ] 예약·취소와 내 예약 조회
- [ ] 사용 시작과 반납 완료 등록
- [ ] 이용 기록 조회
- [ ] AI 요약과 실패 처리
- [ ] Docker 실행과 데이터 보존 검증

첫 작업은 물품을 등록하고 지정 보관 장소를 조회하는 흐름이다. 이후 예약부터 사용 시작·반납 완료까지 연결하고 AI 요약을 추가한다.

## 12. 완료 기준과 개발 기록

다음 흐름이 정상적으로 연결되어야 한다.

**물품 검색 → 예약 → 사용 시작 → 지정 장소에 반납 → 반납 완료 등록 → 다른 사용자의 반납 여부 확인**

T1~T16의 정상·실패 사례와 데이터 보존을 검증한다. 실제 결과, 실행일, 발견한 문제와 수정 내용을 기록하며, 검증 전에는 통과로 표시하지 않는다.

### 동료 검토 기록

검토일, 받은 의견, 반영 내용과 변경 이유를 기록한다.
