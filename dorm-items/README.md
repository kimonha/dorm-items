# 모두의 물품 — 기숙사 공용 물품 예약·사용·반납

첨부 개발 문서의 F1~F7과 이후 요청한 물품별 수량·개별 시간 선택을 구현한 FastAPI 웹 서비스입니다. 예약, 사용, 반납은 서로 구분되며 **학생에게 반납 위치 입력란을 제공하지 않습니다.**

## 지금 실행하기

이 작업 환경에는 필요한 Python 패키지를 설치했습니다. 프로젝트 폴더에서 실행하세요.

```sh
./start.command
```

서비스는 **http://127.0.0.1:8000** 에서 열립니다. FastAPI의 API 문서는 **http://127.0.0.1:8000/docs** 에서 확인할 수 있습니다. 서버 실행에는 Uvicorn을 사용합니다.

macOS에서는 `start.command` 파일을 실행할 수도 있습니다. 새 환경에서 가상환경이 없으면 이 파일이 패키지를 설치합니다. Python 3.10 이상이 필요합니다.

| 역할 | 아이디 | 비밀번호 |
| --- | --- | --- |
| 학생 | student | student123! |
| 다른 학생 | student2 | student123! |
| 관리자 | admin | admin123! |

로컬 모드는 Docker 없이 SQLite를 사용합니다. `dorm-reservations.sqlite3`에 데이터가 보존됩니다. 이 파일은 비밀번호 해시와 이용 내역을 포함하므로 공개 저장소에 올리지 마세요. 이전 버전의 `dorm-local.sqlite3`와 코드는 덮어쓰지 않았습니다. 이전 코드는 `archive/`에 보관했으며, 새 모델로 자동 이전하지 않습니다.

종료는 서버 터미널에서 Ctrl+C입니다. 다른 포트는 `./start.command 8003`처럼 지정하세요. 이미 같은 포트에서 실행 중이면 기존 서버를 종료하거나 포트를 바꿉니다.

새 컴퓨터에서 직접 준비하려면:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

## 사용 흐름

1. 학생으로 로그인하고 물품을 검색합니다.
2. **시간표 확인**에서 날짜와 30분 단위 구간을 선택합니다. 최대 2시간까지 예약합니다.
3. **내 예약과 이용**에서 예약을 확인합니다. 예약 시간에 조회하면 **사용 시작** 버튼이 표시됩니다.
4. 사용 후 **물품에 지정된 장소에 실제로 반납**합니다.
5. **반납 완료 등록**에서 반납 사실을 확인하고 저장합니다.
6. 다른 학생은 물품 화면에서 사용 가능 상태와 최근 반납 완료 등록 시각을 확인합니다.

시연을 위해 서버 시간을 변경하거나 과거 예약을 허용하지 않습니다. 따라서 지금 예약했다면 예약 시작 시각까지 기다려야 사용을 시작할 수 있습니다. 시간에 관한 자동 테스트는 서버의 주입 가능한 시계를 사용합니다.

관리자로 로그인하면 물품·운영 시간 수정, 전체 기록, 처리 이력, 예외 반납과 AI 요약을 사용할 수 있습니다. 다른 이용자의 예외 반납에는 사유가 필요합니다. 관리자도 타인의 예약을 임의로 취소하거나 사용을 시작할 수는 없습니다.

## 운영 규칙

- 운영 요일·시간 안에서 30분 단위, 최대 2시간 예약
- 예약 구간은 `[시작, 종료)` 기준: 14~15시 뒤 15~16시 예약 가능
- 서버에서 저장 직전에 최신 중복 여부 확인
- PostgreSQL에서는 물품 행을 `FOR UPDATE`로 잠그고, 로컬 모드에서는 쓰기 요청만 `BEGIN IMMEDIATE`로 검증과 저장을 직렬화하고, 조회는 WAL 스냅샷을 사용
- 본인 예약만 취소 가능; 이미 사용을 시작한 예약은 반납 후에도 취소 불가
- 미사용 예약은 예약 시간이 지난 경우에도 취소할 수 있음 (문서의 ‘사용 시작 전’ 기준)
- 본인 예약 시간에만 사용 시작; 취소 예약·이전 미반납 이용이 있으면 거절
- 예약 한 건에 이용 기록은 최대 한 건; 재요청은 기존 결과 반환
- 반납 완료 재요청은 기존 시각·결과 반환; 새 이력 생성 없음
- 자동 반납 처리 없음; 예약 종료 후 미반납 이용은 지연 표시
- 반납 시 지정 보관 장소 변경 없음; 위치 필드를 API에 보내도 거절
- 예약·취소·사용·반납·관리자 수정과 처리 이력은 같은 트랜잭션에서 저장
- 기존 유효 예약을 운영 시간 밖으로 만드는 관리자 수정은 거절
- 학생 기록 화면은 본인 예약·이용만 표시; 공용 화면에 다른 학생의 식별 정보 공개 없음
- 한국 시간(Asia/Seoul) 기준; 운영 종료 시각 24:00 지원, 자정 이후로 이어지는 예약은 미지원

## PostgreSQL + Docker Compose

Docker Desktop을 켠 뒤 프로젝트 폴더에서 실행합니다. 예시 환경 파일은 로컬 시연용 계정과 DB 설정을 제공합니다.

```sh
[ -f .env ] || cp .env.example .env
docker compose up --build --wait
docker compose ps
```

서비스는 http://127.0.0.1:8080 에서 열립니다. API 문서는 http://127.0.0.1:8080/docs 에서 확인합니다. 포트를 바꾸려면 `.env`의 `WEB_PORT`를 수정합니다.

`week04` 실습처럼 웹 앱과 PostgreSQL을 각각 실행합니다. DB의 접속 상태가 확인되면 웹 컨테이너가 스키마를 준비하고 Uvicorn을 시작합니다. `/health` 응답의 `database` 값은 이 환경에서 `postgresql`입니다. 발표 전에는 `docker compose ps`에서 두 서비스가 `healthy`인지 확인하고, Compose 환경에서 시연용 예약을 만들어 주세요.

```sh
docker compose logs -f web
docker compose down
docker compose up -d
```

`postgres_data` 영속 볼륨으로 데이터를 보존합니다. **`docker compose down -v`는 볼륨 데이터를 삭제**합니다. DB 포트는 호스트에 노출하지 않습니다. 이미지에는 로컬 DB·환경 파일·이전 코드가 포함되지 않습니다. 최초 초기화는 기존 테이블·데이터를 보존하며, 데모 계정·물품은 없는 경우에만 추가합니다.

이 버전은 `booking_` 접두사의 별도 테이블을 사용하므로 이전 버전의 PostgreSQL 테이블도 덮어쓰지 않습니다. 실제 운영에서는 `SEED_DEMO=false`로 설정하고 다음과 같이 계정을 생성하세요.

```sh
docker compose exec web python app.py create-user 담당자계정 --role admin
docker compose exec web python app.py create-user 학생계정 --role student
```

직접 PostgreSQL을 연결하려면 `DATABASE_URL` 또는 `PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`를 설정하고 `python app.py init-db` 후 `python app.py run`을 실행하세요. 직접 실행 시 `.env`를 자동으로 읽지 않습니다. 환경 변수를 터미널에 설정해야 합니다.

외부 배포에는 HTTPS 프록시를 구성하고 `COOKIE_SECURE=true`로 설정하세요. 기본 포트 바인딩은 로컬 접속용입니다. 로그인 시도 제한, 학교 계정 연동, 알림, 백업 운영은 추가 범위입니다.

## AI 요약

[Google AI Studio](https://aistudio.google.com/apikey)에서 Gemini API 키를 발급받고 프로젝트 폴더의 `.env`에 `GEMINI_API_KEY=발급받은_키`를 저장하세요. 로컬 실행은 기존 서버를 종료한 뒤 아래 명령으로 키를 전달합니다.

```zsh
set -a
source ./.env
set +a
./start.command
```

Docker Compose는 프로젝트 폴더의 `.env`를 읽습니다. 키가 포함된 `.env`는 제출 ZIP에서 제외하세요.


`GEMINI_API_KEY`를 서버 환경 변수에 설정하면 외부 LLM을 호출합니다. 모델은 `GEMINI_MODEL` (기본 `gemini-3.5-flash-lite`), 제한 시간은 `AI_TIMEOUT_SECONDS` (기본 15초)로 설정합니다. 키는 브라우저에 전달하지 않습니다. Docker 환경 변수 변경 후에는 `docker compose up -d`로 컨테이너를 재생성합니다.

- 관리자가 조회 기간을 선택하고 **기간 분석**을 요청
- 해당 한국 날짜들과 겹치는 예약을 조회해 전체 집계
- 예약 건수·예약 시간대 집계는 취소 제외; 취소 건수 별도 표시
- 사용 시간은 사용 시작부터 반납 완료 **등록**까지; 미반납 시간은 완료 이용 시간에 합산하지 않음
- 미반납 지연은 요약 집계 시점 기준, 지연 반납은 등록 시각이 예약 종료보다 늦은 경우
- 기간과 겹치는 예약의 이용 생애 전체를 집계하며, 시간대 예약 분량은 선택 기간 안으로 잘라 계산
- LLM에는 숫자 물품 ID와 숫자 집계·조회 기간만 전송: 계정, 이름, 학번, 호실, 위치, 자유 입력 메모 미전송
- 원본 예약·이용 기록과 집계를 함께 표시, 원본은 페이지당 50건
- 기록 없으면 AI 호출 안 함; API 미설정·오류·시간 초과 시 실패 안내와 집계·원본 유지
- AI 요약은 상태를 자동 변경하지 않음

외부 LLM 응답의 정확성은 관리자가 근거 기록과 대조해야 합니다. API 호출 비용은 사용한 계정에 발생할 수 있습니다.

## 테스트

```sh
.venv/bin/python -m unittest discover -s tests -v
```

임시 SQLite 저장소를 사용하며 서비스 데이터에 영향을 주지 않습니다.

Docker를 사용할 수 있는 환경에서 동일 테스트를 PostgreSQL로 실행하려면:

```sh
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down -v
```

테스트 구성은 서비스 DB/영속 볼륨과 격리됩니다. `TEST_DATABASE_URL`을 직접 설정할 경우 **테스트 전용 DB만** 지정해야 합니다. 테스트가 해당 DB의 `booking_` 테이블을 비웁니다.

## 최신 동작: 수량별 예약과 개별 시간 선택 (2026-11-09)

이 절은 초기 개발 문서의 단일 물품 중복 제한 및 시작·끝 구간 선택 설명보다 우선합니다.

| 물품 | 보유 수량 |
| --- | --- |
| 청소기 | 3 |
| 택배 카트 | 8 |
| 스팀 다리미 | 3 |
| 공용 우산 | 8 |

- 카드의 사용 상태는 **현재 시각**의 예약과 미반납 사용 건을 중복 없이 합쳐 계산합니다. 여유가 하나라도 있으면 사용 가능, 모두 차면 사용 중입니다. 미래 예약은 해당 시간표에서 판단합니다.
- 예: 청소기 3개에 현재 예약·사용 1건이면 사용 가능 2개, 3건이면 사용 중입니다.
- 늦은 미반납도 현재 점유 수량에 포함합니다. 예약 종료 시각이 지나도 실제 사용 수량이 자동으로 비워지지 않습니다.
- 정상 반납 완료된 이용은 점유 계산에서 제외합니다. 미사용 예약은 종료까지 수량을 점유합니다.
- 각 30분 구간의 동시 예약 수가 수량에 도달할 때만 마감합니다. 물품 행 잠금으로 동시 요청을 수량 이하로 제한합니다.
- 동일 사용자는 같은 물품의 겹치는 시간에 중복 예약할 수 없습니다.
- 시간 선택 카드에는 시간과 상태(예약 가능·예약 마감·내 예약·지난 시간)만 표시하며 잔여 개수는 표시하지 않습니다.
- 30분 구간을 각각 클릭해 선택하고, **같은 구간을 다시 클릭하면 그 구간만 해제**됩니다. 다른 선택은 유지됩니다.
- 떨어진 구간은 연속 구간별 별도 예약으로 한 요청에서 함께 저장됩니다. 선택하지 않은 중간 시간은 예약하지 않습니다. 합계 최대 2시간 제한은 유지합니다.
- 여러 구간 중 하나라도 실패하면 전체 요청을 취소합니다. 예약 저장 성공 응답에 최신 시간표를 포함해 즉시 화면에 반영합니다.
- 관리자는 물품 정보에서 수량을 변경할 수 있습니다. 기존 예약의 최대 동시 수량 또는 실제 미반납 수량보다 작게 줄이는 요청은 거절합니다.
- 최초 실행 때 기존 DB에 수량 필드와 초기 수량을 한 번만 추가합니다. 기존 예약·이력은 보존하며 이후 관리자 수량 변경도 재실행 후 유지됩니다.

프런트엔드 테스트: `node tests/test_slot_selection.mjs`, `node tests/test_booking_ui.mjs`

스팀 다리미의 실제 보유 수량은 사용자 정정에 따라 **3개**로 반영했습니다. 예약·사용 수량과 별도로 보유 수량을 유지합니다.

## 미반납 알림

사용 시작을 한 이용 건에서 **예약 종료 시각이 지났고 반납 완료가 없는 경우** 본인에게 알림을 표시합니다. 사용을 시작하지 않은 예약이나 취소 예약에는 반납 알림을 보내지 않습니다.

- 상단 ‘알림’에 미반납 건수 표시, 화면에 미반납 안내와 지정 보관 장소·지연 시간 표시
- 알림의 **반납 완료** 버튼에서 실제 반납 여부를 확인한 뒤 처리
- 반납 완료 후 알림에서 자동 제거
- 페이지가 열려 있는 동안 최대 30초 간격으로 서버 상태 확인, 가장 가까운 예약 종료 직후에도 갱신 예약
- 다른 탭/앱에서 돌아오면 즉시 다시 확인
- 같은 이용 건의 안내 메시지·기기 알림을 계속 반복하지 않도록 해당 브라우저의 localStorage로 중복 방지
- 알림 접기는 화면만 접으며 미반납 기록을 삭제하거나 반납 처리하지 않음
- ‘브라우저 알림 켜기’를 직접 누르고 브라우저 권한을 허용하면 페이지가 실행 중일 때 기기 알림도 제공
- 브라우저가 기기 알림을 지원하지 않거나 권한이 거절되어도 서비스 안의 알림은 동작

페이지를 닫거나 서버를 중단한 동안의 푸시·문자·이메일 발송은 포함하지 않습니다. 비활성 탭에서는 브라우저의 타이머 제한으로 표시가 늦어질 수 있습니다. 본인 소유 이용 건만 서버가 조회하며 클라이언트의 시계나 사용자 ID 입력으로 다른 학생의 알림을 조회할 수 없습니다. 알림 실패는 기본 예약·반납 기능을 중단하지 않습니다.

화면 테스트: `node tests/test_notifications_ui.mjs`
